# Проект API `loadSerpPages(inputUrl, options)`

Будущий API `google-serp-links` собирает все страницы одной выдачи через
проектируемый `save-html.renderPages`. Оба API пока не реализованы.
Существующий `loadSerp` и CLI сохраняют своё поведение.

Диаграмма пагинации: [SEQ-2.mmd](SEQ-2.mmd). Целевая структура:
[Cls-0.mmd](architecture/Cls-0.mmd). Все диаграммы:
[diagrams.html](diagrams.html), через HTTP с общими assets `/mermaid-view/`.

## Вход и результат

```typescript
loadSerpPages(inputUrl: string | URL, options?: SerpPagesOptions): Promise<SerpPagesOutcome>

type SerpResult = {
  title: string;
  url: string;
  snippet?: string;
  result_type?: "organic" | "video" | "app" | "shopping" | "other";
};

type SerpPagesOutcome =
  | { ok: true; data: { query: string; results: SerpResult[] } }
  | { ok: false; error: SerpPagesError };

type SerpPagesError = {
  stage: "input" | "load" | "access" | "parse" | "pagination" | "journal" | "close";
  url: string | null;
  htmlPath: string | null;
  cause: {
    message: string;
    code: string;
    loaderCode?: string;
    status?: number | null;
    htmlUnavailableReason?: string;
    nextPageUrl?: string | null;
    lastAssessment?: SerpAssessment;
    assessmentFailure?: { message: string; code: "serp-assessment-failed" };
    close?: { message: string; code: string };
  };
};
```

`inputUrl` — HTTP(S) URL Google `/search` с одним непустым `q`.
Пустое декодированное значение и строка только из пробелов дают `input`;
проверка пустоты не обрезает принятую строку. Декодированное значение `q`
становится `data.query` и сохраняется дословно, включая пробелы, регистр и Unicode.
Наличие и декодированные значения `hl`, `gl` и остальных защищённых параметров
также сохраняются по правилам ниже. URL-кодирование может
менять представление (`+`, `%20`, percent-encoding), сохраняя значения параметров.

Начальный `start` — неотрицательное безопасное целое; отсутствие означает `0`.
Повторные `start` или защищённые параметры, неверный URL и неподдерживаемые либо некорректные
опции дают `input` до вызова `save-html`.
Вход принимает только `q`, `hl`, `gl`, `tbm`, `tbs`, `lr`, `num`, `start` и
перечисленные ниже служебные параметры. Параметр вне этого списка даёт
`input/unsupported-parameter` до браузера, загрузки или записи HTML.
Это входной список **целевого предложения**, а не подтверждённой реализации.
Для `num`, `tbm`, `tbs`, `lr` обязательны отдельные реальные двухстраничные
наблюдения B1 переноса заявленных **значений/семейств** `вход -> редирект -> next
-> URL второй страницы`. Одна базовая фикстура с `hl/gl` или одно значение tbm
не подтверждают поддержку других режимов/фильтров.
Это уточнение целевого предложения заменяет прежнее принятие неизвестных
входных параметров с последующей защитой их наличия; поведение `loadSerp`/CLI
и его раздел README «Готовый адрес выдачи Google» не меняется.

| Опция | Значение |
| --- | --- |
| `timeout` | Положительное целое, ожидание одной страницы в мс; по умолчанию `30000` |
| `browserChannel` | `chrome` по умолчанию; также `msedge` или `chromium` |
| `profile` | Путь профиля; при отсутствии — общий профиль `save-html` |
| `headless` | Необязательное `true`; `false` и другие значения дают `input` |

Это полный набор опций. Браузером управляет `save-html`; режим всегда
`headless: true`, в том числе при отсутствии этой опции. Лимитов страниц
и результатов нет.

`SerpResult` соответствует элементу `loadSerp(..., {structured: true})` и
`parseSerpData`, а не обычному элементу с `domain`. Обязательны полный `title`
и конечный `url`; непустой нормализованный `snippet` и надёжно распознанный
`result_type` необязательны. `domain`, HTML и пустые необязательные поля не входят
в результат. Извлечение сохраняет действующие ограничения компактного формата
из README; перечень типов не требует угадывать неподдерживаемый тип. Результаты
объединяются в порядке страниц и выдачи; для повторного целевого URL остаётся
первое вхождение со всеми его полями.

Успех возвращается после конца обхода и успешного закрытия браузера.
Все внутренние исключения преобразуются в ошибочный исход: публичный Promise
не отклоняется, частичные `data`/`results` не возвращаются.
`cause` содержит сериализуемые сведения о причине.

## Взаимодействие с `save-html`

`google-serp-links` один раз вызывает `renderPages(inputUrl, options)`, передавая
настройки загрузки, `headless: true`, отключённый логгер, абсолютный `output`,
внутренние callback `assess` и `nextPage`. Публичная опция P `browserChannel`
отображается адаптером в опцию **`channel`** загрузчика; `browserChannel`
не передаётся в `renderPages` или `createBrowserLoader`.

### Готовность страницы

`assess(snapshot) -> {ready, userAction}` может быть асинхронным. Это чистая
проверка Google-разметки через **`SerpMarkupPort.assessPaginatedSerp`**, которую P
передаёт через порт обхода. Внутренний callback возвращает `SerpAssessment`;
адаптер передаёт `save-html` только `{ready, userAction}`. Загрузчик ожидает
проверку, но не знает правил SERP и её диагностических причин.
Проверка не накапливает результаты, не меняет visited-start и не сохраняет файлы.

```typescript
type SerpAssessment = {
  ready: boolean;
  userAction: "captcha" | "consent" | null;
  reason: "ready-pagination" | "ready-single-page" | "ready-empty"
    | "awaiting-serp" | "awaiting-pagination" | "unrecognized-layout" | "access-required";
};
```

Для обычной выдачи `ready: true` требует распознанного каркаса SERP и одного
подтверждённого B1 признака: завершённого блока пагинации, терминального состояния
одностраничной выдачи без навигации или пустой выдачи. Одного результата, `a h3`, события
`complete` или 500 мс стабильного DOM недостаточно: навигация может появиться позже.
Частично появившийся контейнер навигации не считается завершённым блоком;
признак его полноты должен следовать из наблюдений B1, а не из одного совпадения селектора.
Страница без результатов, но с распознанной завершённой пагинацией, допустима.
`ready-pagination` означает завершённый блок с next или без него;
`ready-single-page` — подтверждённый конец с результатами без блока;
`ready-empty` — подтверждённую пустую выдачу. Последние два признака должны
опираться на структуру/метаданные разметки, не на перевод сообщения.
Наличие результатов и отсутствие навигации сами по себе не доказывают конец.
Существующий `inspectHtml.noResults` узнаёт текст только en/ar; он **не является**
языконезависимым доказательством конца для нового API. Селекторы двух состояний
без навигации пока не подтверждены, поэтому их успешная поддержка остаётся B1.
Распознанная ссылка без доступного href допускает готовность, затем даёт
`pagination` в `nextPage`, а не считается концом.

Неизвестная/незавершённая разметка без доказательства готовности даёт `ready: false`.
При истечении `timeout` загрузчик сохраняет доступный HTML и возвращает
`ok: false`, `timedOut: true`, `error: "browser-timeout"`; P даёт **`load`**,
если нет ограничения доступа. **`parse`** означает ошибку разбора после успешной
загрузки, включая нарушение контракта в фикстуре/стабе с `ok: true`, либо ошибку
разбора результатов в уже распознанном каркасе; исключение проверки готовности
также даёт `parse/serp-assessment-failed` по отдельному правилу ниже.
Это разные случаи AC-07, AC-12 и AC-14.
Если готовность распознана, продолжающиеся изменения нерелевантного DOM сами
по себе не заставляют ждать общее окно стабильности и не превращаются в таймаут.

`awaiting-serp` означает, что каркас ещё не появился; `awaiting-pagination` —
каркас/результаты есть, но доказательство навигации или конца ещё не распознано;
`unrecognized-layout` — полученная разметка не соответствует известным признакам;
`access-required` сопровождается ненулевым `userAction`. Только `ready-*` дают
`ready: true`. Это описание наблюдения, а не вывод о скорости сети или причине
изменения Google. Адаптер хранит последний завершённый вердикт **текущей попытки**
и передаёт его P в `page.lastAssessment` внутреннего порта. При таймауте P сохраняет
его в `cause.lastAssessment`, включая `reason`, без HTML и произвольного throwable.
До первой проверки и после callback перед следующей загрузкой состояние очищается;
если проверка ни разу не завершилась, поле отсутствует. Вердикт предыдущей страницы
не используется. `cause.code` при этом остаётся `browser-timeout`.

Пока B1 не подтвердил состояния без блока, одностраничная выдача и пустая выдача
на неподтверждённом `hl` без другого доказательства готовности дают
`load/browser-timeout`, а не успешный неполный или пустой результат.
S по своему [локальному контракту](../../find-chrome-extensions-by-keyword/docs/ARCHITECTURE.md)
добавляет `step: "serp"`, сохраняет ошибку и `cause`, прекращает последующие этапы
и не повторяет P. Этот внешний документ не входит в репозиторий; правило потребителя
записано здесь явно. Таймаут не преобразуется в пустую выдачу. Полезность такого
fallback для редких `site:`-запросов ограничена; она не закрывает B1.

`userAction: "captcha" | "consent"` и собственные признаки загрузчика
останавливают headless-вызов с сохранением доступного HTML. HTTP-ошибка также
не ожидает появления пагинации. Конкретные признаки каркаса, блока и терминальных
состояний должны быть подтверждены фикстурами B1; эта спецификация их не выдумывает.

1. `save-html` открывает один браузер на весь вызов, загружает страницу с `assess`
   и сохраняет HTML успешной страницы либо доступного ошибочного снимка.
2. Передаёт сохранённую страницу в `nextPage(page)` и ожидает его завершения,
   в том числе когда загрузчик вернул `ok: false` с HTML.
3. В callback `google-serp-links` проверяет доступ, исход загрузки и фактический
   URL, парсит выдачу, проверяет `query` и следующую ссылку, накапливает результаты.
4. Callback возвращает следующий URL либо `null` при распознанном конце выдачи.
   Исключение прекращает обход.
5. `save-html` закрывает созданные ресурсы в `finally`. Его `Promise<void>`
   завершается после закрытия; затем `google-serp-links` возвращает исход.

### Нейтральный сбой загрузчика и адаптация

Внешний `save-html.renderPages` отклоняет Promise с `{primaryError, closeError}`.
Каждое поле — `null` либо нейтральный сбой; хотя бы одно поле непустое:

```typescript
type RenderFailure = {
  phase: "open" | "load" | "assess" | "save" | "callback" | "close";
  url: string | null;
  snapshot: { output: string; complete: true } | null;
  error: unknown;
};
```

`snapshot` подтверждает завершённую запись **этой попытки**, а не наличие старого
файла. Для `close` используется последняя сохранённая страница, если она есть.
Для сбоя записи или загрузки без снимка `snapshot: null`. При `callback`
`error` содержит исходное брошенное значение без изменения; загрузчик не читает
его `stage` и не импортирует `SerpPagesError` из P. Он передаёт сбой закрытия
отдельно даже после ошибки записи без вызова callback.

`SaveHtmlPagesAdapter` отображает `open/load -> load`, `assess -> parse`, `save -> journal`,
`close -> close`, проверяет снимок через файловую систему и нормализует причину.
При `callback` сохраняет корректный `SerpPagesError`, сформированный P;
некорректное значение обрабатывает по правилу непредвиденных ошибок ниже.
**Внутренний** `SerpTraversalPort` возвращает тот же Promise<void>, но его
отказ содержит `{primaryError, closeError}` уже с `SerpPagesError`. Так внешний
загрузчик независим от модели P, а ядро не зависит от нейтральных внешних типов.

Исключение/reject из `assess` адаптер помечает приватным маркером текущей попытки
и сохраняет исходную причину; произвольный `error.code` не считается этим маркером.
Внешний renderer различает фазу `assess` по месту вызова callback, сохраняет
доступный снимок, затем передаёт нейтральный сбой с исходным брошенным значением.
`nextPage` при таком сбое не вызывается. Адаптер снимает свой маркер и возвращает
`parse/serp-assessment-failed`: URL снимка, подтверждённый `htmlPath` либо `null`
с причиной. Нет доступного снимка — это не основание менять этап на `load`.
Если запись этого снимка сама не удалась, основным становится
`journal/html-save-failed`, а сохранённая адаптером причина проверки попадает
в `cause.assessmentFailure`. Закрытие всё равно выполняется; его сбой — отдельно
в `cause.close`. Новый generic phase `assess` не вводит в save-html понятия SERP.

P сохраняет основную ошибку и добавляет сообщение/код ошибки закрытия в
`cause.close`; без основной ошибки возвращает `close`. Публичный исход ожидает
завершения загрузчика и закрытия. Формат `SerpPagesError` существует только
в google-serp-links; нейтральный контракт загрузчика — предложение для save-html.

| Поле `page` | Тип | Смысл |
| --- | --- | --- |
| `html` | `string` | HTML полученной страницы |
| `url` | `string` | Фактический URL страницы, в том числе после редиректа |
| `status` | `number \| null` | HTTP-статус конечного ответа; `null`, если статус не получен |
| `output` | `string` | Подтверждённый абсолютный путь сохранённого HTML |
| `ok` | `boolean` | Успешность загрузки |
| `error?` | `string` | Непустой код сбоя; при успехе отсутствует |
| `timedOut?` | `boolean` | Превышено время ожидания |
| `userAction?` | `"captcha" \| "consent"` | Требуется действие пользователя |
| `lastAssessment?` | `SerpAssessment` | Только внутренний порт: последний завершённый вердикт текущей попытки, добавленный адаптером |

Поля с `?` могут отсутствовать. Исходные значения передаются без потери.
В существующем загрузчике `error` содержит фиксированный код;
текст выброшенного исключения обрабатывается отдельно. Коды сравниваются
точно, без поиска подстрок.

Страницы загружаются последовательно, без предварительных запросов и повторов.
Вызывающий код последовательно запускает вызовы API в одном каталоге модуля
или с одним профилем: они используют общий снимок или профиль.

## Пагинация

Следующий URL берётся из HTML; относительная ссылка разрешается относительно
фактического `page.url`. Значение `start` не угадывается.

До следующего запроса проверяется:

- URL ведёт на Google `/search`, `start` и защищённые параметры однозначны.
- Значения и наличие всех защищённых параметров совпадают с исходными.
  Изменённый кандидат не исправляется молча; различия только в кодировании допустимы.
- `start` — неотрицательное целое, строго больше текущего.
- `start` ещё не запрашивался в этом вызове.

Предлагается консервативная политика идентичности:

| Параметры | Допустимые изменения |
| --- | --- |
| `q`, `hl`, `gl`, `tbm`, `tbs`, `lr`, `num` | Значение и наличие неизменны; `q` обязателен |
| Любой другой параметр | Во входе не поддерживается (`input/unsupported-parameter`); появление в фактическом или следующем URL даёт `pagination/search-identity-changed` |
| `ei`, `ved`, `sa`, `source`, `sourceid`, `oq`, `gs_lcrp`, `sei` | Могут добавляться, исчезать или менять значения; не входят в идентичность |
| `start` | Для следующей ссылки строго растёт; у фактического URL равен ожидаемому |

Защищённые параметры не могут повторяться; отсутствие параметра отличается от
пустого значения. Результат сравнения не зависит от порядка параметров и
эквивалентного URL-кодирования. Google-хост может измениться. Остальные послабления
не добавляются автоматически: неизвестные параметры отклоняются во входе,
а при обходе не могут добавляться к защищённой идентичности.
Эта политика и служебные исключения подлежат подтверждению B1; обнаруженное
расхождение требует пересмотра контракта, а не молчаливого исправления URL.
Правило наблюдения переноса применяется также к уже перечисленным защищённым
`num`, `tbm`, `tbs`, `lr`: имена остаются в проекте входа, а допустимые значения
ограничиваются реестром ниже. Поддержка имени целиком из одной фикстуры не выводится.
Если Google удаляет, меняет или заменяет параметр, текущее строгое правило
не объявляется совместимым: до реализации нужно сузить входной список либо
пересмотреть контракт по наблюдению. Автоматическое восстановление параметра
в next и преобразование `tbm` в `udm` не предусмотрены; `udm` пока не поддержан.
Из наблюдаемого размера страницы нельзя вывести перенос `num`, и наоборот:
P не обещает заданное `num` число результатов на странице.

### Подтверждённые значения и семейства входа

Нормативный реестр входит в этот контракт. Каждая добавленная запись указывает
точное значение либо семейство с форматом, допустимыми значениями/границами,
условиями режима и сочетаний `tbm/tbs`, а также ссылки на реальные B1-фикстуры.
Он фиксируется при review версии; пользовательские опции и автоматическое
обучение/расширение списка не добавляются. Проверка принадлежит `SerpSearchIdentity`.

| Параметр | Область, которую может подтвердить B1 | Подтверждено сейчас |
| --- | --- | --- |
| `tbm` | Точное декодированное значение для конкретной вертикали с постраничным next | Нет значений |
| `tbs` | Именованное семейство фильтров: грамматика, ключи, значения/границы, допустимые сочетания и режим tbm | Нет семейств |
| `num` | Перечисленные точные декодированные значения; размер страницы наблюдается отдельно | Нет значений |
| `lr` | Перечисленные точные декодированные ограничения/выражения | Нет значений |

Наличие одного из этих параметров с неподтверждённым значением, семейством или
сочетанием даёт `input/unsupported-parameter` до I/O. Пока реестр пуст, все явно
заданные `num/tbm/tbs/lr` отклоняются; отсутствие этих параметров допустимо.
Имена в проектном списке не означают разрешение произвольных значений.
Сопоставление использует декодированную строку без обрезания, смены регистра или
подстановки алиасов; эквивалентное URL-кодирование допустимо.
Один пример tbs не разрешает любой фильтр с похожим префиксом, новые ключи или
комбинации. Для семейства фиксируются проверенные границы и отрицательные случаи.
После допуска исходное значение/наличие по-прежнему неизменно при обходе.
Режимы с догрузкой прокруткой без постраничного next этим API не поддерживаются;
для их допуска нельзя использовать таймаут либо стабильный DOM как доказательство.

В частности, `ie`, `gs_lp`, `sclient`, `uact`, `iflsig`, `sca_esv`, `sstk`, `sxsrf`
пока **не** входят в разрешённый входной или служебный список. URL из адресной
строки Chrome либо формы Google с ними даёт `input/unsupported-parameter`,
даже при `ie=UTF-8`; ненужный первый запрос не выполняется.
`cause.message` перечисляет неподдерживаемые имена без их значений.
API не удаляет параметры из входа и не правит найденный next автоматически.
Вызывающий код может явно построить поддерживаемый URL, если знает необходимые
параметры поиска; универсальное удаление неизвестных параметров не предлагается,
поскольку их влияние на выдачу не установлено.
Все эти имена и сочетания `sourceid/oq/gs_lcrp/ie` должны проверяться в B1:
нужно наблюдать перенос входных параметров в редирект и next, а не только
тестировать отклонение заранее сконструированных изменений.
После выпуска изменение списка требует сохранённой очищенной фикстуры URL/HTML,
сравнения входа, редиректа и next, обоснования отсутствия влияния на поиск,
проверки отрицательных случаев `q/hl/gl/tbm/tbs/lr/num`, review изменения контракта
и регрессионных тестов, затем записи в примечаниях к новой версии.
Новое имя не добавляется автоматически и не вызывает retry с ослабленной политикой.
До такого выпуска неподдерживаемый вход останавливается с `input/unsupported-parameter`;
параметр, добавленный при обходе, — с `pagination/search-identity-changed`.
`cause.nextPageUrl` сохраняет отклонённую ссылку, если ошибка относится к next.

При фиксированной идентичности страница определяется числовым `start`, независимо
от кодирования URL. `start` отмечается до запроса. Нарушение даёт `pagination`;
отклонённая страница не загружается. `error.url` указывает текущую страницу,
а `cause.nextPageUrl` — отклонённый адрес либо `null`, если распознанная ссылка
не содержит доступного адреса.

После успешного парсинга **`parseSerpPage(html, page.url).query`** должно строго
совпасть с исходным декодированным `q`, включая последнюю страницу без следующей
ссылки. Несовпадение даёт `pagination` до накопления результатов и проверки
следующей ссылки. Это защита контракта порта: новая функция тоже получает `query`
из уже проверенного `page.url`, поэтому обычный редирект с другим `q` отсекается
**до** разбора. Ветка несовпадения возвращённого `query` проверяется стабом парсера,
а не выдаётся за независимую проверку текста запроса в DOM.
Формат `results` остаётся указанным выше.

Отсутствие новых результатов, пустая страница или одни дубликаты не прекращают
обход при допустимой следующей ссылке из распознанной пагинации. Для нового API
парсер расширяется отдельно от сохранённого поведения существующего `loadSerp`:
пагинационный блок может подтверждать выдачу даже с нулём результатов и без
локализованного сообщения «нет результатов».

Новые методы порта/адаптера — `assessPaginatedSerp(snapshot)` и
`parseSerpPage(html, pageUrl)`; они не являются новыми режимами старых функций.
Существующие `assessGooglePage` и `parseSerpData`, их экспорт, результат и
использование в `loadSerp`/CLI **не меняются**. Общие чистые средства извлечения
могут переиспользоваться без изменения прежнего контракта. Новая `parseSerpPage`
возвращает `{query, results, nextLink}` с доказательством готовности/конца;
новые ключи не добавляются в результат существующей `parseSerpData`.

`nextLink = absent | href | missingHref` допустим только вместе с доказательством
навигации/конца: завершённый блок либо подтверждённое B1 терминальное состояние.
Конец — распознанное завершённое состояние блока без ссылки «Следующая» либо
языконезависимый признак одностраничной/пустой выдачи
без следующей ссылки. Одни результаты без блока/маркера не доказывают конец:
`assess` продолжает ожидание; при ложном `ok: true` парсер даёт
`parse` / `google-unrecognized-pagination`. Пустой распознанный конец даёт `[]`.
Нераспознанная разметка после успешной загрузки даёт `parse`; неготовность до
дедлайна даёт `load` по разделу готовности. Селекторы остаются условием B1.

## HTML и ошибки

Каждая полученная страница перезаписывает `debug/page.html` относительно корня
модуля `scripts/google-serp-links`, независимо от рабочего каталога.
Сохранение завершается до callback, включая страницы с ограничением доступа
или ошибкой парсинга. Диагностические JSON и служебный stderr отсутствуют.
После вызова остаётся последний снимок; вызывающий скрипт может скопировать его.

| `stage` | Причина | `error.url` |
| --- | --- | --- |
| `input` | Недопустимый вход | Исходный URL, если представим строкой; иначе `null` |
| `load` | Техническая ошибка, неуспешный исход загрузчика без ограничения доступа, отсутствие статуса или иной ответ вне 2xx | Запрошенный URL при исключении без страницы; иначе фактический `page.url` |
| `journal` | Ошибка сохранения HTML | Фактический URL сохраняемой страницы |
| `access` | CAPTCHA, consent, unusual traffic, HTTP `403`/`429` | Фактический `page.url` |
| `parse` | Ошибка проверки готовности или разбора/обработки выдачи | Фактический URL снимка, иначе URL текущей попытки |
| `pagination` | Недопустимый редирект, несовпадение разобранного `query` или следующая ссылка | Текущий фактический `page.url`; отклонённая следующая ссылка — в `cause.nextPageUrl` |
| `close` | Ошибка закрытия без основной ошибки | Фактический URL последней сохранённой страницы; если её нет — `null` |

`htmlPath` указывает существующий полный снимок соответствующей попытки.
Для недопустимой следующей ссылки это HTML страницы, содержащей её;
для недопустимого редиректа — HTML полученной страницы.
Если снимка нет или его существование нельзя подтвердить, возвращается `null`
и `cause.htmlUnavailableReason`. Старый или неполный файл не подставляется.

Порядок обработки: сохранение → проверка доступа → проверка исхода загрузки →
проверка фактического URL → парсинг → проверка разобранного `query` → следующего URL.

Классификация после сохранения HTML: применяется первое подходящее правило.

| Признак страницы | Исход |
| --- | --- |
| `userAction` равен `"captcha"` или `"consent"`, независимо от `error`/`ok` | `access` |
| HTTP `403`/`429`, признаки ограничения в HTML, Google `/sorry/` или `consent.google.*` | `access` |
| `error` равен `user-action-required`, `manual-action-timeout` или `captcha-repeated` | `access` |
| `error` равен `browser-timeout` или `browser-page-closed` | `load` |
| Любой другой непустой код `error` | `load` |
| `ok: false`, `timedOut: true` или статус вне `200–299`/равен `null` | `load` |
| `ok: true`, нет кода ошибки и таймаута, статус `200–299` | Проверка фактического URL и парсинг |

При `access` или `load` парсинг не выполняется; причина загрузчика сохраняется
в `cause`. Ограничение прекращает сбор без обхода и повторов.

Фактический URL должен быть Google `/search` с однозначными параметрами,
исходной защищённой идентичностью (включая `gl`), а также `start` текущего запроса
(отсутствие `start` означает `0`). Редирект может менять Google-хост и только
перечисленные выше служебные параметры. Нарушение даёт `pagination` до парсинга.

### Коды и непредвиденные ошибки

`cause.code` обязателен и не определяется разбором `message`. Предлагаемые
устойчивые значения для нового API:

| `stage` | `cause.code` |
| --- | --- |
| `input` | `invalid-url`, `invalid-search-url`, `missing-query`, `empty-query`, `invalid-start`, `unsupported-parameter`, `duplicate-parameter`, `invalid-option`, `input-processing-failed` |
| `access` | `google-consent`, `google-blocked`, `http-403`, `http-429`, либо точный известный код `user-action-required` / `manual-action-timeout` / `captcha-repeated` |
| `load` | Точный непустой код `page.error`, включая неизвестный; иначе `browser-timeout`, `http-<status>`, `status-unavailable`, `page-load-failed`; для исключений — `browser-launch-failed`, `renderer-contract-violation`, `renderer-unexpected-error`, `unexpected-callback-error` |
| `parse` | `google-unrecognized-page`, `google-unrecognized-pagination`, `serp-parse-failed`, `serp-assessment-failed`, `serp-accumulation-failed`, `unexpected-callback-error` |
| `pagination` | `invalid-redirect`, `invalid-next-url`, `duplicate-parameter`, `search-identity-changed`, `invalid-start`, `redirect-start-changed`, `nonincreasing-start`, `repeated-start`, `missing-next-href`, `parser-query-mismatch`, `unexpected-callback-error` |
| `journal` | `html-save-failed` |
| `close` | `browser-close-failed` |

Для входа действует первое нарушенное правило в таком порядке:

| Проверка входа | `input/cause.code` |
| --- | --- |
| Значение невозможно разобрать как абсолютный URL | `invalid-url` |
| Схема не HTTP(S), хост не Google или путь не `/search` | `invalid-search-url` |
| Повторный `start` или защищённый параметр | `duplicate-parameter` |
| Нет `q` | `missing-query` |
| Декодированный `q` пуст или только из пробелов | `empty-query` |
| Начальный `start` не является неотрицательным безопасным целым | `invalid-start` |
| Есть параметр вне перечисленного входного списка | `unsupported-parameter` |
| Значение/семейство/сочетание `num`, `tbm`, `tbs`, `lr` не входит в подтверждённый реестр | `unsupported-parameter` |
| Опции не соответствуют полной таблице | `invalid-option` |

Десятичные цифры задают целое `start`; дробь, знак, экспонента, пустое значение
и число вне `Number.MAX_SAFE_INTEGER` не принимаются. Отсутствие означает `0`.
Тот же синтаксис используется в полученном и следующем URL.

После классификации доступа/загрузки для URL применяется первое нарушенное правило:

| Порядок / нарушение | Фактический URL | Следующая ссылка |
| --- | --- | --- |
| 0. Распознана next, но href недоступен | Не относится | `missing-next-href` |
| 1. Не разбирается URL, неверная схема/Google-хост/путь `/search` | `invalid-redirect` | `invalid-next-url` |
| 2. Повторный `start` или защищённый параметр | `duplicate-parameter` | `duplicate-parameter` |
| 3. Изменены значение/наличие защищённого параметра, включая отсутствующий `q` | `search-identity-changed` | `search-identity-changed` |
| 4. Недопустимый синтаксис/диапазон `start` | `invalid-start` | `invalid-start` |
| 5. Допустимый `start` отличается от ожидаемого текущего | `redirect-start-changed` | Не относится |
| 6. Допустимый `start` уже запрашивался | Не относится | `repeated-start` |
| 7. Допустимый новый `start` не больше текущего | Не относится | `nonincreasing-start` |

`invalid-redirect` не используется для изменения `gl` или другого защищённого
параметра. Проверка visited **предшествует** росту: после `start=20,30` ссылка
на `20` даёт `repeated-start`, ссылка на новый `25` — `nonincreasing-start`.
Изменение `gl` вместе с повторным start сначала даёт `search-identity-changed`;
повтор самого параметра start сначала даёт `duplicate-parameter`.
Проверка результата `parseSerpPage.query` выполняется после проверки фактического
URL и до проверки next, с единственным кодом `parser-query-mismatch`.

При нескольких признаках `access`: `userAction` имеет первый приоритет,
затем HTML/URL consent, HTML/URL CAPTCHA или unusual traffic, затем `403/429`,
затем известный код загрузчика. Consent даёт `google-consent`, CAPTCHA/unusual
traffic — `google-blocked`. `cause.status` сохраняет статус, `cause.loaderCode`
сохраняет исходный код загрузчика, если есть: CAPTCHA при `429` различима с
обычным HTTP `429`. Неизвестный код без признаков доступа остаётся `load`;
подстроки не распознаются. Низкоуровневый код исключения также можно сохранить
в `loaderCode`, но внешний `Error` не попадает в публичный JSON.

После исключения `access` код неуспешной страницы выбирается по порядку:
непустой `page.error`, иначе `timedOut: true -> browser-timeout`, иначе
`status: null -> status-unavailable`, иначе статус вне 2xx -> `http-<status>`,
иначе `ok: false -> page-load-failed`. Фазы исключений `open` и `load`
отображаются соответственно в `browser-launch-failed` и `page-load-failed`;
фаза `assess` имеет только `parse/serp-assessment-failed`.

P фиксирует текущий шаг callback до его выполнения. Непредвиденный throw/reject
в проверке метаданных загрузки получает `load`, в инспекции/разборе HTML — `parse`,
в проверке URL/query/следующей ссылки — `pagination`, в накоплении — `parse`.
Для непредвиденных сбоев код `unexpected-callback-error`, кроме выделенного
`serp-assessment-failed`/`serp-accumulation-failed`; контекст — текущая сохранённая
страница. Корректная уже классифицированная ошибка не переклассифицируется.
Сбой `assess` имеет отдельный путь `parse/serp-assessment-failed` через адаптер
по разделу нейтральных сбоев; он не маскируется под `load/page-load-failed`.

Синхронный throw внешнего `renderPages` или произвольный отказ вне callback
даёт `load/renderer-unexpected-error`. Некорректный `{primaryError,closeError}`
даёт `load/renderer-contract-violation`. URL — последний ожидаемый адрес,
изначально `inputUrl`; без достоверного контекста попытки `htmlPath: null` и
`htmlUnavailableReason`. Старый общий файл не используется как доказательство.
Неожиданный сбой проверки входа даёт `input/input-processing-failed` без загрузки.
Непредвиденное значение callback, дошедшее до адаптера без нормализации P,
даёт `parse/unexpected-callback-error` с контекстом нейтрального сбоя.

Нормализация умеет обрабатывать Error, строки, null, циклические объекты и
значения с бросающим преобразованием в строку. Если безопасное сообщение получить
нельзя, используется фиксированное `Unknown failure`. Публичные `cause` и
`cause.close` содержат только сериализуемые данные; ошибки нормализации не
приводят к отклонению публичного Promise. Закрытие всё равно ожидается.

Сбой записи имеет приоритет перед проверками callback: даже HTML с `429`
в этом случае даёт `journal`.

Закрытие обязательно при любом исходе. Ошибка закрытия фатальна из-за общего
профиля. При наличии основной ошибки её `stage`, `url` и `htmlPath` сохраняются,
а сведения о сбое закрытия добавляются в `cause.close`. Без основной ошибки
возвращается `stage: "close"` вместо успеха. Повторное закрытие или новый браузер
не запускаются.
Повторное использование профиля требует подтверждённого освобождения.

## AC для unit-тестов

Критерии относятся к будущей реализации. Если не указан сбой закрытия,
оно считается успешным.

### Вход

- **AC-01.** Неверный URL, повторные параметры и неверные или неизвестные опции
  дают `input`; `renderPages`, создание браузера, callback и запись HTML не выполняются.
  Отсутствие `headless` и `headless: true` допустимы; `false` и другие значения — `input`.
  Отсутствующий `q` — `missing-query`, `q=` и только пробелы — `empty-query`,
  отрицательный/дробный/пустой/слишком большой начальный `start` — `invalid-start`,
  не-Google-хост, неверная схема или путь — `invalid-search-url`;
  неразбираемый URL — `invalid-url`. При нескольких нарушениях соблюдается
  порядок таблицы входа, без создания ресурсов.
  `ie=UTF-8`, `gs_lp`, `sclient`, `uact`, `iflsig`, `sca_esv`, `sstk`, `sxsrf`
  и произвольное неизвестное имя во входе дают `unsupported-parameter`:
  `renderPages` не вызван, запросов и файлов нет. Сообщение содержит только имена.
  URL с `q/hl/gl` и известными `sourceid/oq/gs_lcrp` проходит input;
  добавленный к нему `ie=UTF-8` даёт `unsupported-parameter` до первой загрузки.
  При пустом реестре явно заданные `num/tbm/tbs/lr` дают `unsupported-parameter`
  без I/O. В UT с тестовым реестром, содержащим только `tbm=nws`, значение nws
  принимается, а `tbm=isch`, пустое значение, иной регистр и неизвестный режим
  отклоняются до renderPages. Это тест правила допуска, не реальное подтверждение nws.
  Для tbs проверяются допустимые и недопустимые значения/границы одного семейства,
  другой ключ/семейство и неподтверждённое сочетание с tbm; num/lr допускают только
  внесённые строки. Сообщение об отказе перечисляет имена без их значений.
- **AC-02.** В цепочке страниц `query` равен исходному декодированному `q`;
  пробелы, регистр, Unicode, значение и наличие защищённых параметров сохраняются,
  включая отсутствующий `hl`, теги `en-US`/`zh-Hant`, регистр и заданный `gl`.
  Эквивалентные варианты кодирования, включая `+` и `%20`, принимаются.
- **AC-03.** Без опций `renderPages` получает `timeout: 30000` и
  **`channel: "chrome"`**; публичный `browserChannel` не утекает во внешний API.
  Неуказанный `profile` использует `defaultProfile`
  из `save-html`.
  Переданные `timeout`, `profile` и допустимый канал (`chrome`, `msedge`, `chromium`)
  сохраняются. Также передаются `headless: true`, логгер без вывода,
  абсолютный `output` модуля и callback `nextPage` и `assess`.
  Адаптер отображает `browserChannel` в `channel`; UT адаптера проверяют реальные
  аргументы `renderPages`, а не только аргументы внутреннего порта P.

### Пагинация и результаты

- **AC-04.** Обход начинается с переданного `start` (по умолчанию `0`).
  Следующая ссылка извлекается из HTML и разрешается относительно фактического URL;
  неравномерные значения `start` используются без угадывания.
- **AC-05.** Недопустимый адрес, повторные защищённые параметры, изменение значения
  или наличия защищённых параметров (`q`, `hl`, `gl`, `tbm`, `tbs`, `lr`, `num`
  и неизвестные вне служебного списка), нецелый, отрицательный или нерастущий `start`
  дают `pagination` до запроса независимо от кодирования URL.
  `error.url` — текущий `page.url`,
  `htmlPath` — снимок этой страницы, `cause.nextPageUrl` — отклонённый адрес
  или `null`, если следующая ссылка распознана, но адрес не получен.
  Проверяются заданный/отсутствующий `gl`, добавление и удаление параметров;
  изменения только разрешённых служебных параметров принимаются.
  Для каждого допущенного значения/семейства `num`, `tbm`, `tbs`, `lr` фикстуры проверяют сохранение
  значения/наличия в фактическом URL и next, а также отказ при удалении, изменении
  или замене. Реальное происхождение положительных фикстур подтверждается B1;
  синтетический отказ не считается доказательством переноса Google.
  Проверяются коды и порядок таблицы URL, включая уже посещённый `20` и новый
  меньший `25` после цепочки `20,30`: `repeated-start` и `nonincreasing-start`.
  Неизвестный параметр во входе отклоняется по AC-01. При добавлении такого имени
  в фактический URL или next из поддерживаемого входа проверяется
  `search-identity-changed`; next не загружается. Для известных служебных
  параметров отдельно проверяется исчезновение/изменение без ошибки идентичности.
- **AC-06.** Длинная конечная цепочка (например, 120 страниц) проходится полностью,
  включая пустые страницы с распознанной пагинацией и страницы дубликатов. `renderPages` не получает
  параметров, ограничивающих число страниц или результатов.
- **AC-07.** Распознанный завершённый блок без next либо подтверждённое B1
  терминальное состояние возвращает `null` из callback без нового запроса.
  Обязательны отдельные реальные B1-фикстуры одностраничной выдачи с результатами
  без навигации и пустой выдачи на целевом `hl != en/ar` (например, `tr`).
  Для подтверждённых языконезависимых признаков первая даёт все результаты,
  вторая — `[]`, обе с `ready: true`, без полного ожидания timeout.
  Если признаки ещё не подтверждены, фиксируется незакрытое покрытие B1:
  UT не объявляют успех по отсутствию блока или по строке en/ar.
  Неизвестная разметка при успешной загрузке даёт `parse`.
  Фикстуры покрывают результаты без блока/маркера (`google-unrecognized-pagination`
  при `ok: true`), пустую промежуточную страницу с next, пустой конец и missingHref.
  Ожидание такой неготовой страницы до дедлайна отдельно проверяется как `load` в AC-12.
- **AC-08.** Итог сохраняет порядок страниц и результатов; дубликаты внутри
  страницы и между страницами оставляют весь объект первого вхождения.

### Загрузка и снимок

- **AC-09.** Используется один браузер с явным `headless: true`.
  Следующая загрузка ждёт асинхронный callback; одновременных загрузок и повторов нет.
  `assess` также ожидается; результат, появившийся раньше блока пагинации,
  не запускает сохранение/nextPage до готовности. Изменения прочего DOM не
  задерживают готовую выдачу; assess не меняет накопление и visited-start.
  Вызывается новый `assessPaginatedSerp`; существующий `assessGooglePage`
  остаётся проверкой для loadSerp с прежним поведением.
- **AC-10.** После сохранения callback вызывается ровно один раз с HTML,
  фактическим URL, статусом, подтверждённым путём и исходными
  `ok`/`error`/`timedOut`/`userAction`, в том числе при `ok: false` с HTML.
  Исключение открытия/загрузки даёт `load`, исключение записи — `journal`;
  в этих случаях callback не вызывается.
  Во внешнем отказе это нейтральные phase `open/load/save`; адаптер отображает
  их в публичные этапы. Для `callback` исходное брошенное значение сохраняется.
  Исключение/reject `assess` даёт нейтральную фазу `assess`, снимок сохраняется
  до отказа, nextPage не вызывается; адаптер даёт `parse/serp-assessment-failed`.
- **AC-11.** Все страницы перезаписывают один абсолютный `debug/page.html`
  до callback. Путь не зависит от `cwd`; JSON-файлы и служебный stderr отсутствуют.

### Ошибки

- **AC-12.** Сохранённый HTML с CAPTCHA, consent, unusual traffic или `403`/`429`
  даёт `access`, даже при неизвестной разметке. Такой же исход дают признаки
  ограничения в `userAction`/`error` по таблице классификации. Проверяются все
  перечисленные коды и приоритет `userAction`: неизвестный `error` вместе
  с `userAction: "captcha"`/`"consent"` даёт `access`; без признаков ограничения —
  `load`. Код, только содержащий известный код как подстроку, считается неизвестным.
  Без ограничения `ok: false`, `timedOut: true`
  или непустой `error` дают `load`, даже при HTTP `200` и распознаваемой выдаче.
  Остальные статусы вне `2xx` (включая `404`, `500`, конечный `3xx`) и `null`
  также дают `load` без парсинга. Успешная загрузка с `2xx` допускает разбор.
  Ошибка парсинга даёт `parse` без проверки следующей ссылки;
  сбой записи HTML с `429` даёт `journal` до callback.
  Неготовая разметка после `timeout` даёт `load/browser-timeout` со снимком,
  а не `parse`; ошибки успешного разбора имеют коды из таблицы.
  Проверяются `cause.code`, `status`, `loaderCode` и приоритет нескольких признаков.
  На неподтверждённых одностраничной/пустой выдачах без блока проверяется
  `load/browser-timeout` с `cause.lastAssessment.reason: "awaiting-pagination"`
  либо `unrecognized-layout` по реальному вердикту. Отдельно проверяются
  `awaiting-serp`, отсутствие вердикта до первой проверки и очистка между страницами.
  S сохраняет эту ошибку, останавливается и не трактует её как успешный пустой ответ.
- **AC-13.** Редиректы на Google `/sorry/` и `consent.google.*` дают `access`.
  При допустимом HTTP-статусе другой выход за Google `/search`, повторные параметры
  или изменение защищённой идентичности (включая `gl` и остальные параметры)
  либо текущего `start` дают `pagination` до парсинга с соответствующим `cause.code`.
  Допустимый редирект сохраняет поиск и текущий `start`; относительные ссылки
  разрешаются от конечного URL. Для `access`, `parse` и недопустимого редиректа
  `error.url` равен фактическому `page.url`.
  После разбора `parseSerpPage(...).query` сравнивается с исходным `q` до накопления;
  несовпадение даёт `pagination`. Проверяется редирект с другим `q` на последней
  странице без следующей ссылки: он отклоняется до парсинга, частичные результаты
  не возвращаются. Ветка `parser-query-mismatch` проверяется отдельно стабом порта;
  она не считается независимым извлечением запроса из DOM.
  Изменение `gl` даёт `search-identity-changed`, выход за Google `/search` —
  `invalid-redirect`, изменение допустимого текущего start — `redirect-start-changed`;
  повторные параметры и неверный start имеют собственные коды по таблице.
- **AC-14.** Исключения всех этапов, включая синхронный throw и отклонённый Promise
  callback, останавливают обход. Публичный Promise возвращает `ok: false`
  с ровно четырьмя полями верхнего уровня `error` (`stage`, `url`, `htmlPath`,
  `cause`) и контекстом из таблицы. Необязательные поля `cause` допускаются;
  частичные данные отсутствуют. Оба исхода и вложенная `cause.close`
  сохраняют свои значения после JSON-сериализации.
  Проверяются unexpected throw в классификации, парсинге, проверке next и накоплении,
  синхронный throw renderPages, произвольный reject и неверный конверт; этап и контекст
  соответствуют явным fallback-правилам. `cause.code` обязателен; Error, строка, null,
  циклическое значение и бросающее преобразование не отклоняют публичный Promise.
  Сбой нового assess проверяется отдельно: `parse/serp-assessment-failed`,
  фактический URL снимка и полный htmlPath; при недоступном снимке — null с причиной.
  Сбой записи этого снимка — `journal/html-save-failed` с `cause.assessmentFailure`;
  приватная отметка адаптера и исходный throwable не попадают в публичный JSON.
- **AC-15.** При `access`, `parse`, `pagination`, `load` с сохранённым HTML и `close`
  возвращается путь существующего полного снимка соответствующей страницы,
  если он подтверждён, включая таймаут и закрытие страницы при HTTP `200`.
  Для отсутствующего, старого, неполного снимка или ошибки
  проверки файла — `htmlPath: null` с `cause.htmlUnavailableReason`.
  UT адаптера отличают нейтральное подтверждение полной записи этой попытки от
  просто существующего старого файла и от отсутствующего контекста renderer.

### Закрытие

- **AC-16.** При успехе и ошибках созданные ресурсы закрываются ровно один раз;
  исход ожидает закрытия. Несозданный ресурс не закрывается.
- **AC-17.** Сбой закрытия после успешного обхода даёт `close`. При основной
  ошибке её `stage`, `url`, `htmlPath` и прежняя причина сохраняются;
  сбой закрытия добавляется в `cause.close`. В обоих случаях результаты,
  повторное закрытие и новый браузер отсутствуют.
  Проверяются сочетания ошибок `load` + `close`, `journal` + `close` без вызова
  callback и ошибка callback + `close`: `renderPages` передаёт обе ошибки с контекстом
  в нейтральном `{primaryError, closeError}`; адаптер отображает их независимо.
  Также проверяются `assess` + `close` и запись снимка после сбоя `assess` + `close`:
  основные коды/контекст и `cause.assessmentFailure` не теряются.
  `cause.close.code` сохраняется; модель P не импортируется загрузчиком.

UT P используют HTML-фикстуры и стаб внутреннего `SerpTraversalPort`;
UT `SaveHtmlPagesAdapter` — стаб внешнего `renderPages` и файловой системы;
UT `renderPages` — стабы браузерной загрузки и файловой системы.
Порядок действий и ожидание callback/закрытия проверяются журналом вызовов
и управляемыми Promise. Интеграционные тесты проверяют реальный браузер
и освобождение профиля.

## Условие начала реализации

До реализации обязательны реальная двухстраничная фикстура доступной выдачи
с `hl` не `en`, отдельная одностраничная выдача без навигации и пустая выдача
на целевом `hl != en/ar` (например, `tr`): HTML, фактическая ссылка «Следующая», результаты
разбора и конечные URL. Она должна подтвердить дословное равенство декодированного
`q`, сохранение защищённой идентичности (включая `gl`), целочисленный рост `start`,
признаки готовности, блока пагинации и распознанного конца. Порядок появления
результатов и навигации фиксируется отдельно; один конечный HTML не доказывает
правильность раннего assess. Подробный протокол и матрица случаев находятся в
[PAGINATION_FIXTURE_PROTOCOL.md](PAGINATION_FIXTURE_PROTOCOL.md).
Дополнительно обязательны **отдельные двухстраничные серии для каждой записи
реестра** `num`, `tbm`, `tbs`, `lr`: точный вход, оба HTML/конечных URL и исходный href next,
доказательство присутствия и неизменности исследуемого параметра на каждом шаге.
`num=10` из нынешнего CLI проверяется первым, вместе с иным значением num;
для каждого заявленного tbm записывается режим и возможное появление udm.
Для каждого семейства tbs указываются грамматика, границы и допустимые сочетания;
наблюдение одного значения не объявляет поддержку всего параметра или семейства.
Ни hl/gl-фикстура, ни URL с четырьмя параметрами сразу не заменяют эти серии.
Пока серии отсутствуют, записи реестра не добавляются и соответствующие явно
заданные параметры дают input. Условие начала реализации остаётся открытым;
поддержка базового q/hl-входа и поддержка опциональных режимов учитываются отдельно.
Следующая страница загружается один раз по обнаруженной ссылке, без угадывания.
При ограничении доступа проверка прекращается; если Google меняет параметры,
контракт пересматривается по наблюдениям до реализации.
Одностраничная и пустая фикстуры должны дать языконезависимые признаки конца;
неудача наблюдения оставляет их поддержку незакрытой и включает описанный load-fallback.
URL, скопированные из адресной строки и формы поиска, наблюдаются отдельно
от минимального `q/hl`-входа S. `ie`, `gs_lp`, `sclient`, `uact`, `iflsig`,
`sca_esv`, `sstk`, `sxsrf` и сочетания с `sourceid/oq/gs_lcrp` проверяются
как кандидаты для пересмотра входного/служебного списков; наблюдение не добавляет
их в списки автоматически. До подтверждения P отклоняет такой вход без I/O.

В исторической локальной проверке получены HTTP `429` и CAPTCHA; второй страницы нет.
Её контекст приведён в протоколе этого репозитория; внешний каталог не нужен
для чтения требований. Блокер остаётся открытым:
подготовленные UT-фикстуры не подтверждают поведение реальной пагинации.
Реальные одностраничная и пустая фикстуры также пока отсутствуют; успешная
поддержка выдач без навигации этим документом не объявляется.

### Статус B1 и зависимый охват AC

3 октября 2026 года базовое наблюдение с `hl=tr`, `gl=tr` снова завершилось
HTTP `429` и CAPTCHA. После первого запроса проверка остановлена;
[очищенные снимки и запись наблюдения](fixtures/b1-2026-10-03/README.md)
подтверждают только ограничение доступа. Условия готовности/конца и списки
параметров остаются проектируемыми; подтверждённые селекторы не добавлены.

| Открытое условие | Зависимый успешный охват |
| --- | --- |
| Готовность завершённой пагинации; конец одностраничной/пустой выдачи; порядок появления результатов и навигации | AC-06, AC-07, готовность в AC-09 и AC-12 |
| Реальная цепочка `вход -> конечный URL первой страницы -> href next -> конечный URL второй страницы`: сохранение `q/hl/gl`, рост `start`, изменения служебных параметров | AC-02, AC-04, положительные переходы AC-05 и AC-13 |
| Отдельные наблюдения URL адресной строки и формы поиска | Совместимость этих входов по тем же AC; до review неизвестные имена отклоняются |

Эти AC сохраняют идентификаторы и описывают целевое поведение, но пока не
являются подтверждённой приёмкой реальных выдач. Синтетические UT сравнения URL,
отказов и timeout-fallback можно подготовить отдельно; они не закрывают B1.
Реестр `num/tbm/tbs/lr` остаётся пустым: отказ при их явном указании определён
однозначно, а положительная поддержка каждой записи требует собственной серии.
Зависимые успешные критерии в `acceptanceCriteria.md` фиксируются после
подтверждения этих условий и согласования контракта с наблюдениями.
